# NesisAI — Backend

FastAPI service that receives patient and prescription data extracted by the Chrome extension and returns clinical alerts generated by the AI pipeline (Gemini + retrieval-augmented generation over pgvector).

For readers unfamiliar with the Brazilian context, see the [Brazilian Health Care Context](../README.md#brazilian-health-care-context) section in the main README.

## Setup

```bash
cd backend
cp .env.example .env   # Set GEMINI_API_KEY
docker compose up --build
```

- API: `http://localhost:8000`
- OpenAPI UI: `http://localhost:8000/docs`
- Health check: `http://localhost:8000/health`

The container runs `alembic upgrade head` before starting the API.

## Main Endpoint

```text
POST /api/v1/analyze
```

The endpoint accepts a Portuguese-keyed payload because it mirrors the fields extracted from the Brazilian e-SUS APS interface:

```json
{
  "paciente": {
    "nome": "Roberto Ferreira",
    "idade": 65,
    "sexo": "M",
    "peso": "70 kg",
    "altura": "170 cm",
    "alergias": [],
    "problemas_condicoes": ["Hypertension", "Heart failure"],
    "med_em_uso": []
  },
  "medicacoes": [
    {
      "nome": "Enalapril",
      "dose": "10 mg",
      "frequencia": "once daily",
      "via": "oral"
    }
  ]
}
```

Key names translate as follows:

| API key | Meaning |
|---|---|
| `paciente` | Patient |
| `medicacoes` | Prescribed medications |
| `nome` | Name |
| `idade` | Age |
| `sexo` | Sex |
| `peso` / `altura` | Weight / height |
| `alergias` | Allergies |
| `problemas_condicoes` | Problems and conditions |
| `med_em_uso` | Medications already in use |
| `frequencia` / `via` | Frequency / route |

Required fields:

- `paciente.nome`: string
- `paciente.idade`: integer from 0 to 130
- `medicacoes`: list; each item requires `nome`

Optional patient fields are `sexo`, `peso`, `altura`, `motivo_consulta`, `objetivo`, and `avaliacao`. The list fields `alergias`, `problemas_condicoes`, and `med_em_uso` default to empty lists. Optional medication fields are `dose`, `frequencia`, `via`, and `posologia_completa`.

The response contains `alertas` and totals grouped by severity:

```json
{
  "alertas": [
    {
      "severidade": "MODERADO",
      "titulo": "Clinical alert",
      "descricao": "Description of the finding",
      "fonte": "Cited source",
      "medicamentos_envolvidos": ["Drug A", "Drug B"],
      "recomendacao": "Recommended clinical review"
    }
  ],
  "total_grave": 0,
  "total_moderado": 1,
  "total_leve": 0
}
```

The API retains the application's Portuguese severity values: `GRAVE` (severe), `MODERADO` (moderate), and `LEVE` (mild).

## Knowledge Base (RAG)

The `nesis_knowledge_base` pgvector collection is populated from [`data/cardio_knowledge.json`](data/cardio_knowledge.json), which currently contains 41 cardiovascular entries.

With the Compose services running:

```bash
docker compose exec backend python scripts/ingest_knowledge.py

# Verify the number of stored embeddings
docker compose exec postgres \
  psql -U nesis -d nesis \
  -c "SELECT COUNT(*) FROM langchain_pg_embedding;"
```

The ingestion script supplies each entry's ID to langchain-postgres. Running it again updates entries with the same IDs rather than intentionally creating new IDs.

`PGVECTOR_URL` must use the host `postgres` inside Docker and `localhost` when the backend runs directly on the host.

## Technology Stack

- FastAPI
- SQLAlchemy 2 (async) + Alembic
- PostgreSQL 16 with pgvector (`pgvector/pgvector:pg16`)
- LangChain + langchain-postgres
- Google Gemini through `langchain-google-genai`
- Embeddings through the newer `google-genai` SDK
- Docker Compose with a named PostgreSQL volume

## Quick Validation

```bash
curl -X POST http://localhost:8000/api/v1/analyze \
  -H "Content-Type: application/json" \
  -d '{
    "paciente": {
      "nome": "Roberto Ferreira",
      "idade": 65,
      "sexo": "M",
      "peso": "70 kg",
      "altura": "170 cm",
      "alergias": [],
      "problemas_condicoes": ["Hypertension", "Heart failure"],
      "med_em_uso": []
    },
    "medicacoes": [
      {"nome": "Enalapril", "dose": "10 mg", "frequencia": "once daily", "via": "oral"},
      {"nome": "Spironolactone", "dose": "25 mg", "frequencia": "once daily", "via": "oral"}
    ]
  }'
```

Look for `RAG recuperou N documentos para: ...` in the backend logs to confirm that vector retrieval ran.
